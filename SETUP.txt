8. FIRESTORE SETUP (do this once)
================================================================
   a. console.firebase.google.com > Add project (NOT garrett-apps).
      Skip Google Analytics.
   b. Build > Firestore Database > Create database > Start in
      PRODUCTION mode > pick a region > Enable.
   c. Build > Authentication > Get started > Sign-in method >
      Anonymous > Enable. (The ops console signs in this way; the
      subject app never authenticates.)
   d. Firestore > Rules tab > paste the contents of firestore.rules
      from this repo > Publish.
   e. Project settings (gear) > scroll to "Your apps" > click the
      web icon </> > register an app > COPY the firebaseConfig object.
   f. Paste that object in TWO places, replacing "null":
        index.html   -> var FIREBASE_CONFIG = null;
        gpi.html     -> var FIREBASE_CONFIG = null;
      It should end up looking like:
        var FIREBASE_CONFIG = { apiKey:"...", authDomain:"...", ... };
   g. Re-upload both files. Bump gpi.html's version badge and the
      CACHE string in sw.js together whenever gpi.html changes.

   VERIFY: open gpi.html, log in, the mode line should read
   "MODE: LIVE — synced as <YOURNAME>." If it says AUTH FAILED, step (c)
   was missed.

     is game-grade, not bank-grade. Keep nothing in Firestore you would mind
     him eventually seeing.

9. INSTALL + NOTIFICATIONS (v0.5)
================================================================
   Joe's app is now a real installable PWA:
     silo.webmanifest, silo-192.png, silo-512.png, sw.js

   IMPORTANT: there is now ONE service worker (sw.js) shared by both
   apps, because both live at the repo root and only one SW can own a
   scope. Cache name is silo-v0.5. Bump it on EVERY content change or
   installed phones will keep serving old files.

   HOW IT BEHAVES
     - An INSTALL banner appears when the browser offers it.
     - An INTAKE ALERTS banner asks for notification permission.
     - Once granted, a pushed sighting raises a real system notification
       with vibration; tapping it deep-links straight to that record
       (index.html#VAD-0128).
     - Anything missed while the app was closed shows up on next open.

   True background push (phone fully closed) needs Cloud Messaging and a
   Cloud Function, which needs the Blaze plan. See push-notifications.txt.
   The push listener in sw.js is already written and dormant.

10. EXTERNAL DOCUMENTATION LINKS
================================================================
   Every record's detail sheet now ends with an EXTERNAL DOCUMENTATION
   block: aerial imagery search, Crop Circle Connector, Circle Research
   Archive, encyclopedia entry (where one exists), open web search, and
   r/cropcircles threads. Plus SATELLITE and GOOGLE EARTH buttons that
   open the exact coordinates.

   display: "NONE ON FILE. THIS INTAKE HAS NOT BEEN PUBLISHED TO ANY
   COOPERATING ARCHIVE." That contrast is the point. Fifty-one records

   UNDOCUMENTED array in index.html. Pushed records are automatic.
